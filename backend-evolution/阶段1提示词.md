请使用 `backend-evolution` Skill，对当前仓库执行阶段 A：现状调查。

本阶段只允许分析和读取，不修改业务代码、配置、数据库结构、依赖文件或现有测试。

请完成以下任务：

1. 识别项目的技术栈、目录结构、所有后端服务及其职责。
2. 梳理各服务的 API 路由、Controller、Service、Repository、DTO 和领域模型。
3. 分析服务间的 HTTP/RPC 调用、消息队列、缓存及数据库依赖。
4. 找出核心业务流程、状态流转、权限校验和关键数据写入位置。
5. 尽可能从路由、调用关系、测试、文档及客户端代码中识别现有接口的调用方。
6. 找出共享组件、公共 DTO、跨服务契约和可能影响多个客户端的高风险模块。
7. 识别现有测试、构建命令、CI 检查及项目约定。

将结果写入 `docs/backend-evolution/01-current-state.md`。

每项重要结论尽可能附上真实的文件路径、类名、方法名或接口路径。区分已证实事实、推断和待确认事项。

如果仓库过大，请按服务分批调查，并记录尚未检查的范围。不要根据目录名称直接推断服务行为。

完成后请汇报：
- 服务清单与依赖关系
- 核心业务链路
- 可能的改造风险
- 未确认的问题
- 实际检查过的范围

此阶段完成后停止，不要开始修改代码。
